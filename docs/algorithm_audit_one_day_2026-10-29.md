## Prototype correction

The dashboard VQE paths previously put the raw eigenvalue of the active-space qubit Hamiltonian in a field named `electronic_energy_hartree`. They now retain that value as `raw_active_space_energy_hartree`, add the active-space constant for `electronic_energy_hartree`, add nuclear repulsion for `total_molecular_energy_hartree`, and pass through optimizer status metadata when Qiskit provides it. Optional exact references keep the raw qubit-space eigenvalue for a like-for-like VQE error comparison and also report corrected electronic/total values. The energy helper was already used by the quantum MCP path; this change aligns the dashboard local and WSL paths with it. In the installed Qiskit version, the direct `OptimizerResult` omits `success` and `message`; the API reports `optimizer_status_available: false` rather than implying convergence from that metadata.

## Verification and limits

- Mocked energy tests cover local and worker paths. Resource-policy, candidate-pipeline, target identity, API, and benchmark integrity suites passed together: 69 tests.
- Direct statevector VQE on a two-qubit test Hamiltonian: VQE `-1.0198037556809032 Ha`, exact `-1.019803902718557 Ha`, absolute error `1.4704e-7 Ha`, 10 optimizer iterations / 75 evaluations. Qiskit's result did not expose a convergence-success flag or message. This validates optimizer plumbing and the numerical result against the exact toy Hamiltonian, not molecular chemistry.
- Quantum-kernel demo and HTTP route ran on synthetic demonstration data; the route returned HTTP 200. These results are not a molecular drug-activity result.
- Saved EGFR metric artifacts were not edited. The saved pilot is the only quantum EGFR result available; no per-compound quantum predictions exist for the repeated scaffold-validation splits.
- Live WSL integration in this session was unavailable: `Wsl/Service/E_ACCESSDENIED`. Windows `.venv-win` lacks both PySCF and pytest; no dependencies were installed. The pytest-style `tests.test_vqe` module therefore could not be run under `unittest`; direct VQE execution and the unittest-based regression suite were used instead.
- No physical quantum hardware job was submitted. Nothing here establishes binding, affinity, efficacy, safety, or quantum advantage.

## Short demo procedure

1. Activate the existing Windows environment and start FastAPI with `python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000`.
2. Start the Next.js app from `frontend-next` with `node node_modules/next/dist/bin/next dev -p 3000`.
3. For the molecular pipeline, upload a PDB with supported target identity evidence and select its target chain when needed. Candidate provenance and resource-policy outcomes appear in the dashboard. A VQE calculation only runs for a molecule allowed by the configured resource policy and when WSL is available.
4. The Quantum Kernel Lab runs its synthetic classification/regression illustration. Do not interpret its scores as drug activity.
5. View saved EGFR reports through the Benchmarks area for the scaffold-aware classical and matched pilot comparisons.
